# REST Enhanced v1.7.5.680

Vulkan safety and automatic scene-colour matching improvements for ReShade 6.8+.

- Skip manual Vulkan effect rendering inside active passes and on targets without required copy support, avoiding the unsafe Auto Scene Colour off path seen in Enshrouded.
- Extend automatic target matching to same-aspect scene images down to quarter output dimensions, supporting combinations of DLSS/upscaling and reduced render scale. Manual matching modes are unchanged.
- Preserve Vulkan attachment usage instead of automatically adding sampling access where native transient restrictions are unknown.
- Add optional FP16 scene-copy support for eligible images that already support sampling. It stays disabled by default; enable `REST_VULKAN_SCENE_TRANSFERS=1` for the game process before launch and restart. No resource shim may be active. See [setup and limitations](../troubleshooting.md#enshrouded-vulkan-testing) and the [safety review](../vulkan-transfer-safety.md).
- Add an optional bounded Vulkan trace for diagnosing shader targets and safe injection boundaries, disabled during normal use.

## Validation and release status

Prepared as a full stable-release candidate, not a GitHub pre-release. Publishing remains pending final local Modern/Legacy checks. The code at Modern commit `08a497c` passed Enshrouded SDR/HDR scene-placement checks with DLSS Quality at 100% and 67% render scale, group/Auto toggles, shader-hunting navigation, a windowed/fullscreen round-trip and clean exit. Version stamping does not change that rendering code. Legacy backport runtime checks and final BG3 D3D11/Vulkan tests are still pending; they must not be reported as passed yet.

Enshrouded required `--keep-vulkan-layers`, the optional scene-copy switch, and the process-only `RESHADE_DISABLE_GRAPHICS_HOOK=1` exit workaround. A suitable earlier scene shader was selected; marking the final UI draw remains too late. These results verify the tested placement and stability, not HDR colour accuracy or universal Vulkan allocation compatibility. The existing depth-stencil-in-use warning persists. Warframe issue #22 is not claimed resolved. See the [candidate validation record](../release-candidate-validation-20261117.md).
