REST Enhanced v1.7.1.680 adds first-class per-group shader visibility control for HUD-free screenshots, shader identification and configuration testing.

## Hide marked shaders

Groups now include a **Hide marked shaders** option. When enabled on an active group, REST suppresses graphics draws matching that group's marked pixel or vertex shaders.

This makes an existing `UI` group useful as a configurable HUD toggle: mark the UI shaders, enable **Hide marked shaders**, and use the group's normal hotkey to hide or restore the HUD without a separate UI-mask add-on.

The same option can also be used temporarily on groups such as `Before Fog` to see exactly what the marked shaders contribute.

### Safety and behaviour

- Supports normal, indexed and typed indirect graphics draws.
- Uses OR semantics when multiple groups match a draw: any active matching group requesting suppression hides the draw.
- Preserves the match across repeated draws that reuse the same bound pipeline, so UI elements do not reappear after the first skipped draw.
- Clears queued REST effect, binding, constant and preview work for skipped calls so it cannot leak into a later draw.
- Compute dispatches are deliberately not suppressed because compute shaders may perform lighting, simulation, upscaling or other non-visual pipeline work.
- Existing configurations remain unchanged because the new option defaults to off.

## Configuration and UI

- Persists through INI save/load.
- Participates in configuration dirty-state tracking.
- Preserved by group cloning and Copy group / Import group.
- Adds a compact **Hide shaders** indicator to configured groups.
- Documents HUD-free screenshot and photo-mode style usage in the README.

## Validation

Runtime testing confirmed the feature works correctly with the existing UI-group workflow, including repeated HUD draws and hotkey toggling.

Both x64 and x86 builds pass architecture, version metadata and required add-on export validation.

Requires **ReShade 6.8 or newer**.
