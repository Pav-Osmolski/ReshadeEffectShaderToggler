REST Enhanced v1.6.1.633 focuses on shader-hunting usability, configuration safety and runtime hardening, with additional Vulkan stability work.

## Highlights

- Responsive shader-hunting workspace with a 540 px preferred pane, a wider default Group Settings window and an adaptive two-column shader list for large result sets.
- One deterministic first-seen shader order is now shared by the list, Prev/Next, marked navigation and direct selection. The two-column view follows the same visual order: down the left column, then down the right.
- Press-and-hold navigation, Mark + Prev / Mark + Next, Copy hash, Rescan and retained hunting UI state make large shader collections much faster to work through.
- Copy group / Import group supports portable group sharing through REST's existing INI format. Imported groups start inactive with no hotkey to avoid unexpected changes.
- Configuration writes are crash-safe: REST writes and verifies a temporary INI, refreshes `ReshadeEffectShaderToggler.ini.bak`, then atomically replaces the live file. A config version field is now included for future migrations.
- Auto Scene Colour diagnostics now keep grouped **Recent candidates** rather than logging every Waiting/Matched/Successful transition as a separate attempt.
- The ReShade add-on author metadata now credits **alex / DeViLhoOD**.

## Stability and optimisation

- Fixes a false unsaved-changes state after opening shader hunting and finishing without changing the committed marks.
- Fixes two-column list clicks selecting the wrong shader by resolving selections directly by shader hash.
- Fixes Vulkan device loss during sustained held Prev/Next navigation. Preview-image recreation now flushes ReShade's immediate command list and waits for the Vulkan graphics queue to become idle before old preview resources are destroyed, preventing recorded or in-flight GPU work from referencing freed images.
- Adds Vulkan pending-work fast paths so deferred preview and Auto Scene Colour matching are skipped when there is no work waiting, while render-pass/subpass bookkeeping remains unchanged.
- Replaces per-overlay full configuration-signature generation with cached dirty-state tracking.
- Caches sorted technique-picker metadata on ReShade effect reload/reorder and avoids unnecessary shader-hash/technique-set copies.

## Validation and compatibility

BG3 Vulkan was used as the primary regression target. The existing Before Fog configuration and Auto Scene Colour path remained correct while testing the updated responsive hunting UI, direct hash selection, deterministic two-column navigation and sustained held Prev/Next cycling across many shaders and preview targets.

The Vulkan preview lifetime fix was specifically stress-tested after a reproducible `VK_ERROR_DEVICE_LOST` during held navigation; after the fix, the same sustained navigation test completed without observed crash or device loss.

The release workflow builds both x64 and x86, validates PE architecture, version metadata and required exports, and publishes a SHA-256 checksum. This does not imply in-game validation of every title, architecture or graphics configuration. A fresh DX11, same-resolution Vulkan or x86 in-game runtime test was not performed for this release.

D3D10/11/12 retain their existing Auto Scene Colour staging path. Vulkan retains the safe-boundary, image-blit staging and resource-state restoration introduced in v1.6.0.633.

## Installation

Extract `release.zip` and place `ReshadeEffectShaderToggler.addon64` (64-bit) or `ReshadeEffectShaderToggler.addon32` (32-bit) beside the game executable used by ReShade. Existing INI configurations remain compatible.

See the included README, changelog and Automatic Scene Colour documentation for setup and limitations.
