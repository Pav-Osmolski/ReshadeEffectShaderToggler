# Getting started

[Documentation index](README.md) · [Troubleshooting](troubleshooting.md)

## Choose the correct release

| Your ReShade installation | REST release line |
|---|---|
| ReShade 6.8 or newer, with full add-on support | Modern (`.680` version suffix) |
| ReShade 5.8–5.9.2, with full add-on support | Legacy (`.580` suffix); ReShade 5.9.2 recommended |
| Older than ReShade 5.8 | Unsupported |

Download `release.zip` from the appropriate [GitHub release](https://github.com/Pav-Osmolski/ReshadeEffectShaderToggler/releases). The repository's Latest release is Modern; Legacy has its own clearly labelled release. The final version component identifies the SDK baseline, not a game version.

## Install or upgrade

1. Close the game. If upgrading, back up `ReshadeEffectShaderToggler.ini` and any customized helper shaders first.
2. Find the executable ReShade actually loads into. For some games this is a shipping executable in a subfolder, rather than the launcher.
3. Copy the matching binary beside that executable: `.addon64` for a 64-bit game or `.addon32` for a 32-bit game. Match the game's architecture, even when Windows itself is 64-bit. Replace the previous REST binary rather than loading duplicate versions.
4. Copy the supplied `Shaders/REST_*.fx` files into a ReShade effect search folder, commonly `reshade-shaders/Shaders`. Ensure the ReShade include search paths can find `ReShade.fxh`. REST calls these helpers when needed; they do not need to be enabled as ordinary global effects.
5. Launch the game, open the ReShade overlay and confirm REST appears under **Add-ons**. Reload effects if you installed or updated helper files, and resolve any shader compile errors first.
6. Keep your existing INI when upgrading. Changing release line or renderer is not a reason to overwrite a working configuration automatically; back up and test before replacing it.

`release.zip` contains both architectures, the helper shaders, README, changelog, docs and build information. Packages generated by the shared packager include a separate optional BG3 configuration ZIP; `SHA256SUMS.txt` covers both ZIPs. GitHub's automatically generated source archives are source code, not compiled add-on packages.

## Make a first group

1. Show the game element or scene boundary you want to identify, then create a **New group** in REST.
2. Name the group and open **Settings**. Start shader hunting, collect the scene, browse the shaders and mark the relevant ones. Use **Rescan** when a new scene needs collecting.
3. In **Effects**, select techniques and keep those techniques globally enabled in ReShade. Their global order still applies.
4. For supported scene-colour/upscaler use, enable **Auto scene colour** in the render-target settings. It uses the primary colour target and may stage to native resolution. It preserves, but temporarily ignores, the manual target/SRV and alpha-preservation settings.
5. Test the group's Active switch or hotkey. Finish editing with **Done**, then use **Save changes** when the unsaved indicator appears.

To hide a HUD rather than inject effects, use **Hide marked shaders** with the relevant pixel/vertex shaders. Compute dispatches are not suppressed. Multiple shader hashes may be needed for different HUD elements.

Read [Automatic Scene Colour](automatic-scene-colour.md) before choosing a boundary around fog, UI or an upscaler. Vulkan must wait for a safe pass boundary and a suitable transfer-capable target; an unsupported target does not become valid merely by enabling Auto.

## Optional BG3 configurations

`BG3-Configs-D3D11+Vulkan.zip` contains separate D3D11 and Vulkan INIs. Use the folder matching the renderer you launch. The shader hashes and injection points can depend on game version, graphics settings and upscaler settings.

Back up your current INI before copying a supplied configuration; that is a replacement, not a merge. To retain existing groups, prefer **Copy group / Import group** rather than overwriting the whole file. Imported groups start inactive with no hotkey so you can test them first. The configuration archive's README and provenance describe its source; being packaged with a release does not establish new game-test coverage.

## Save and recover

Use **Save changes** to persist edits. REST uses a verified temporary file and maintains `ReshadeEffectShaderToggler.ini.bak` from the previous configuration. This does not protect a file you manually overwrite outside REST: keep a separate backup before installing example configs.

If needed, close the game, preserve the current INI, restore a known-good backup as `ReshadeEffectShaderToggler.ini`, and restart. Check the selected techniques and hotkeys before continuing.

For HDR, start with [HDR handling and validation](HDR.md). A preview is a diagnostic texture view, and **Apply tone map clamping** is not automatic HDR10/PQ conversion.
